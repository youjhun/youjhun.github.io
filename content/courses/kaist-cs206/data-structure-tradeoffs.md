> [!abstract] 한눈에
> 자료구조는 어떤 연산을 얼마나 자주 하는지에 따라 고른다. 어느 쪽이 더 빠른지는 그 조건 없이 정할 수 없다. 시간복잡도와 함께 메모리 사용, 캐시 지역성, 구현 불변식을 본다.

## Big-O의 의미

$O(f(n))$은 입력 크기 $n$이 커질 때 실행시간이나 추가 메모리가 얼마나 빠르게 증가하는지의 상한을 표현한다. 상수와 낮은 차수 항을 숨기므로 작은 입력의 실제 속도를 그대로 예측하지는 않는다.

최악, 평균, 상각 분석을 구분해야 한다. 동적 배열의 append는 가끔 전체 복사를 하지만 여러 번의 append에 비용을 나누면 상각 $O(1)$이다.

## 배열과 연결 리스트

| 연산                | 배열              | 단일 연결 리스트                   |
| ------------------- | ----------------- | ---------------------------------- |
| 인덱스 접근         | $O(1)$            | $O(n)$                             |
| 앞 삽입             | $O(n)$            | 머리 포인터가 있으면 $O(1)$        |
| 알려진 노드 뒤 삽입 | 이동 필요 가능    | $O(1)$                             |
| 메모리              | 연속, 지역성 좋음 | 포인터 추가, 노드가 흩어질 수 있음 |

연결 리스트의 삽입이 $O(1)$이려면 삽입 위치의 노드를 이미 알고 있어야 한다. 위치를 찾는 데 $O(n)$이 걸리면 전체 연산도 $O(n)$이다.

## ADT와 구현 분리

스택은 LIFO, 큐는 FIFO라는 행동 규약이다. 배열이나 연결 리스트는 이를 구현하는 방법이다. 인터페이스가 push/pop을 약속하고 구현은 크기, head/tail, 연결 관계 같은 불변식을 지킨다.

재귀 알고리즘은 호출 스택을 암묵적으로 사용한다. 종료 조건과 매 호출에서 문제가 작아진다는 사실을 함께 증명해야 한다. 그렇지 않으면 무한 재귀나 예상보다 큰 메모리 사용이 생긴다.
